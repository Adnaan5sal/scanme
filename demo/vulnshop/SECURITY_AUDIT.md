### 1. IDOR: GET /api/orders/:id returns any user's order

**In plain terms** — Any logged-in user can reach other users' private records just by changing an ID in the URL.

| | |
|---|---|
| **Severity** | 🔴 CRITICAL |
| **Location** | `server.js:137` |
| **Found by** | detect.py (semantic check semgrep has no rule for) |
| **Evidence** | Tier 1 — reproduced against a running instance |
| **How it was proven** | Bob(uid2) GET /orders/4471 -> 200 with Alice card_last4 4242; anon -> 401 |
| **What we did** | Fixed, and locked behind a regression test |
| **Guarded by** | `test_order_idor.js` |

The vulnerable code that was found and replaced:

```
const order = db.prepare('SELECT * FROM orders WHERE id = ?').get(Number(orderMatch[1]));
```


### 2. SQL injection in GET /api/search

**In plain terms** — An attacker can run their own database commands through your app - reading, changing, or deleting any data it can reach.

| | |
|---|---|
| **Severity** | 🔴 CRITICAL |
| **Location** | `server.js:155` |
| **Found by** | detect.py (sink is node:sqlite, unknown to rulesets) |
| **Evidence** | Tier 1 — reproduced against a running instance |
| **How it was proven** | q=' OR '1'='1 returned all 3 products vs 1; UNION reached users table |
| **What we did** | Fixed, and locked behind a regression test |
| **Guarded by** | `test_search_sqli.js` |

The vulnerable code that was found and replaced:

```
const rows = db.prepare("SELECT id, name, price FROM products WHERE name LIKE '%" + q + "%'").all();
```

## What this audit does **not** tell you

This is the most important section for anyone reading the grade above.

- **The grade covers what was examined, and nothing else.** A clean result on the classes checked says nothing about the ones that were not.
- **It cannot prove the absence of vulnerabilities.** "No proven findings" means nothing was demonstrated — not that nothing is there.
- **It is a code audit, not a penetration test.** Running infrastructure, network configuration, TLS setup, DNS, and cloud IAM were not touched.
- **Business-logic flaws need product knowledge.** A discount that can be applied twice, or a workflow step that can be skipped, is invisible without knowing the intended behaviour.

**Specifically not checked in this run:**

- File upload handling (the app has none)
- CSRF (no cookie-based sessions)
- SSRF (no outbound requests)
- Dependency vulnerabilities (zero third-party dependencies)
- Rate limiting, account lockout, password policy
- Deployment configuration, TLS, security headers
